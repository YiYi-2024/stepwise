# 北极星设计系统交接指南

交付时请发送整个「北极星设计系统」文件夹，保留相对路径。前端从共享样式、模板和行为脚本封装组件；产品经理从已有页面布局出发，用同一套组件拼接业务流程。

在收到的文件夹内运行以下命令，再打开[组件目录](http://127.0.0.1:8765/index.html)、[六种布局预览](http://127.0.0.1:8765/index.html#general/layout)或[首页 DEMO](http://127.0.0.1:8765/DEMO/)。这些地址指向访问者自己的电脑。

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

## 人与 AI 共用的执行入口

前端封装组件库时走 A，产品经理生成演示页面时走 B。人可以用下表交代任务，AI 收到任务后按相应一列执行。文件路径均相对于本指南所在目录。

| 步骤 | A · 封装组件 | B · 生成 DEMO |
| --- | --- | --- |
| 1. 确定输入 | 确认要迁移的组件、目标工程和一次真实调用场景。从目标工程读取框架和目录约定。 | 确认入口、用户动作和预期结果，从布局页选择初始状态。需求已给出的信息直接沿用。 |
| 2. 找到依据 | 从组件目录定位预览，再追到共享模板、样式、脚本和 token。记录组件接收的数据、支持的状态及发出的事件。 | 找到最接近的 DEMO，逐项对应页面区域与已有组件。例如“查看产物”复用文件输出、顶部页签和三栏布局。 |
| 3. 实现 | 在目标工程封装并导出组件，接入真实调用入口。让同页多个实例分别持有焦点、展开状态和复制目标。 | 在 DEMO 中实现可操作的完整路径。复用共享组件；示例内容、模拟数据和页面间联动放在场景层。 |
| 4. 验证并交付 | 给出导入方式、最小调用示例和已验证的状态。说明哪些事件仍需业务接入。 | 给出预览入口、可复现的点击路径和模拟行为。写明已验证结果与尚未核对的细节。 |

**如何处理差异。** 本次需求明确修改某条规则时，把变更应用到对应范围。共享组件的修改同时检查组件预览与 DEMO；单页布局调整留在页面层。尺寸与交互优先查本次指定的 Figma 节点和对应组件。来源互相矛盾时，记录具体元素、差异和采用的依据。仅当缺失信息会改变交付结果时提问，例如要求封装到某个工程，但没有提供目标工程或技术栈。

**如何判定完成。** 从正常入口触发动作，核对可观察的结果。按本次改动选取相关场景：

| 起始状态与动作 | 应看到的结果 |
| --- | --- |
| 两个输入框同时存在，在第二个输入框选择附件并移除 | 只有第二个输入框的附件列表与发送状态变化。 |
| 中文输入法选词后按回车，再在候选词确认后按回车 | 第一次确认候选词，第二次发送。Shift＋回车换行。 |
| 连续发送两条消息，等第二轮正文结束，再点第二轮反馈栏的复制 | 每轮各有一个反馈栏，剪贴板内容对应第二轮正文。 |
| 打开一个产物，再打开任务摘要 | 中间对话栏宽 480px，右侧显示该产物的页签，摘要在对话栏上方浮动。 |

**可直接交给 AI 的任务句式**

- A：「读取本指南，按 A 路径，把［组件］封装到［目标工程］。调用场景为［场景］。请实现、验证并给出最小调用示例。」
- B：「读取本指南，按 B 路径，为［用户］生成［业务流程］的 DEMO。完成条件为［可观察结果］。请交付可打开的本地页面。」详细需求可使用文末模板。

## 前端：从现有实现封装组件库

当前交付物是可交互的 HTML、CSS 和原生 JavaScript。正式库的框架和发布方式由接入项目决定。建议先迁移一个完整流程验证接口，再按需扩大范围。

| 要封装的内容 | 现有依据 | 迁移方式 |
| --- | --- | --- |
| 颜色、文字、图标 | [样式入口](polaris.css)、[语义色](tokens/semantic.css)、[基础规格](tokens/foundation.css)、[资源](assets/) | 保留 CSS 变量和资源路径映射。普通图标复用 mask 并继承颜色，彩色文件类型图标用原图。检查全局 base.css 对宿主页面的影响。 |
| 按钮、提示、面板、菜单项 | [基础按钮](components/button.css)、[提示](components/tooltip.css)、[下拉](components/select.css)、[级联](components/cascader.js) | 提取尺寸、图标、禁用、选中、箭头等已有变体。提示方向由触发场景决定。上传菜单和技能子菜单共用面板与选项。 |
| 对话输入、附件、发送 | [输入组件预览](pages/chat/chat-input.html)、[行为脚本](components/chat-input.js) | 复用文件块、图片、技能标签和模式选择。将输入值、附件列表、模式和运行状态映射到宿主框架，向业务层发出发送、移除、切换事件。 |
| 消息、流式过程、反馈与摘要 | [共享模板](components/chat-parts.js)、[思考过程](components/thinking.js)、[摘要行为](components/task-summary.js) | 每轮消息用稳定 ID 关联正文、附件、反馈和产物。渲染过程接收阶段和内容增量；复制目标指向本轮正文。 |
| 导航、页签和工作区 | [主导航](components/mainbar.css)、[导航菜单](components/mainbar-menu.js)、[顶部导航](components/navbar.css)、[布局页](pages/general/layout.html)、[任务页编排](DEMO/task.js) | 组件负责显示、键盘操作和事件，业务页面持有项目、会话、文件页签及布局状态。布局页可作为组合后的验收样例。 |

**建议从“选文件 → 发送 → 收到回复”这一条链路开始。** 对照预览找到同一组件的默认、悬停、聚焦、禁用和运行态，保留已有的 `pl-` 类名及 DOM 结构作为首版视觉基准。先封装图标按钮、文件块和下拉选项，再组装输入框，最后把组合后的输入框放回首页与任务页验证。

例如，输入框可以接收 `value`、`attachments`、`mode`、`running` 和菜单展开方向，发出 `onSend({ text, attachments, mode })`。这些是**建议接口**，命名可随技术栈调整。文件选择器产生的 File、上传进度、服务端文件 ID 和失败重试由接入业务提供。现有 DEMO 处理本地缩略图和文件元信息，流式回复使用模拟数据。

封装交互时，把当前脚本的页面级查询和监听收进组件实例，在卸载时清理监听、观察器和定时器。菜单、tooltip 和复制目标使用实例唯一 ID。用同页两个输入框、连续两轮回复验证状态隔离；再用键盘验证回车发送、Shift＋回车换行、中文输入法确认候选词和菜单关闭后的焦点。产物多开时检查页签滚动、切换和关闭。

交付前用真实业务入口核对样式和资源能否加载，随库提供公共导出、样式入口、使用示例，以及变体和事件说明。新增通用组件时同步更新组件目录和预览页。基础约定见 [CONVENTIONS.md](CONVENTIONS.md)，具体交互以对应组件和已经确认的场景为准。目录里仍有占位预览，排期时应逐项确认实现程度。

## 产品经理：基于现有规则生成 DEMO

先写清用户从哪里进入、要完成什么、点击后哪些区域发生变化，再选布局。布局页包含首页、对话、任务摘要、三栏编辑、三栏摘要、编辑器全屏六种状态。首页可从 [DEMO/index.html](DEMO/index.html) 起步，任务流程可从 [DEMO/task.html](DEMO/task.html) 起步。新场景放到 DEMO 目录的独立页面或子目录，引用共享组件与资源。

| 场景 | 生成时沿用的规则 |
| --- | --- |
| 框架与布局 | 桌面主导航宽 240px。常规对话正文与输入框同列居中，最大宽 768px，两侧至少留 24px。打开产物后，中间对话栏固定 480px，编辑器占剩余宽度。优先复用布局预览里的实际页面。 |
| 输入与附件 | 加号展开上传菜单，输入框保持默认边框。图片用缩略图，其他文件按类型显示图标、名称和大小，长名称省略。首页的模式面板向下展开，任务内页向上展开。 |
| 对话流 | 用户气泡最大宽 624px。消息组内底部预留 30px 操作区，再与 AI 回复间隔 16px。生成时先显示扫光，再展开思考计时，结束后折叠并输出正文。每轮正文完成后显示本轮反馈。 |
| 消息定位 | 满 3 条用户消息显示刻度，默认等长。悬停时相邻刻度逐级伸缩，300px 宽的浮层随刻度平滑移动，提问一行、回复最多三行。三栏模式隐藏刻度。 |
| 摘要与产物 | 点击任务摘要切换开合。面板距离底部至少 40px，内容在面板内滚动。编辑器已打开时，摘要作为浮层。点击产物打开或激活对应页签，溢出时用共享翻页按钮。 |
| 视觉与新需求 | 从 polaris.css 引入样式，颜色按语义 token 匹配，复用现有 icon、悬停和选中态。具体到技能回写等已有特例，直接沿用组件。遇到组件库尚未覆盖的状态，列出差异及需要设计确认的内容。 |

### 可直接复制给生成工具

```text
请在北极星设计系统的 DEMO 目录新增一个可运行的演示页面。
目标用户与任务：[谁，从哪里进入，要完成什么]
采用布局：[从布局页选择初始状态，写出后续切换状态]
交互路径：[用户动作 → 界面变化 → 完成条件]
演示数据：[项目名、用户提问、附件、回复、产物；注明哪些是模拟数据]
需要展示的边界状态：[例如长文件名、多文件、空态或生成中]

先查看 pages/ 下的组件预览、components/ 下的实现及最接近的 DEMO 页面。
列出“页面区域 → 复用组件 → 需要传入的数据”，然后实现。
沿用 polaris.css、现有图标、共享行为和布局规则，页面只补场景编排。
输出可打开的入口、操作路径、模拟行为，以及需设计确认的差异。
```

**验收例子**：从首页上传一张图片和一份 PDF → 输入提问并回车 → 任务页的用户消息展示两份附件 → 思考完成后自动收起 → 回复结束后出现反馈 → 点击产物打开第三栏 → 再点任务摘要，确认浮层打开且页签仍可切换。用这条路径可以同时检验组件复用、状态联动和布局是否一致。
